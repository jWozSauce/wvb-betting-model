## 2. Elo ordering and leakage

`vbstats/elo.py:90` sorts by start time then contest ID, snapshots ratings
at `:109`, and applies points afterward at `:135`. Micro-tests verify that
a game's points cannot affect its own snapshot; conference offsets change
only across conferences; 0.8 carryover shrinks the deviation correctly and
resets game counts. Full chained replay verifies team-games = twice matches
for each season 2021–25 (`core-1/checks.json`).

**Risk:** start-time ordering is not finish-time ordering. A later contest
can receive conference information from a game that started simultaneously
or shortly earlier but had not finished. A two-game same-start example
shows this directly; the later ID sees the earlier result. This is a real
temporal weakness, with effect on headline accuracy unquantified. Freeze
simultaneous/overlapping snapshots or reconstruct availability time in a
separate evaluation task. Modal venue construction also uses whole-season
venue counts, rather than only information available before each fixture.

## 3. Set model and uncertainty

Independent recursive enumeration of all legal best-of-five set sequences
matches the six-outcome implementation over 75 combinations of strength,
fifth-set shrink and latent variance. Maximum component difference is
1.11e-16; probabilities are positive and sum to one within floating-point
error. A separate normal-density integration at fitted variance agrees
within 1.7614e-9. These checks test the formula, not forecast calibration.
See `scripts/audit/core_audit.py` and `core-1/checks.json`.

`vbstats/model.py:77` uses one shared latent match shock, with fifth-set
probability `0.5 + lambda*(p-.5)` clipped to the probability interval. The
fitted covariance is positive definite (minimum eigenvalue 6.69e-5). With
seed 7, 10/500 normal parameter draws put lambda outside [0,1]; clipping
keeps valid probabilities but this is an approximate Laplace posterior,
not evidence that all tail quantiles are calibrated. App p20 is the 20th
percentile of each market's parameter-draw probability, not a lower bound
on the realized match outcome. Complementary p20 probabilities need not
sum to one. Player coefficients have no analogous posterior uncertainty.

Equal-team home ML is .578926, matching the approximate 57.9% claim.
Neutral-but-labeled home ML is .587353: the intercept remains and the fitted
home feature coefficient is negative. Only explicit symmetrization yields
.5. Thus interpreting the entire intercept as causal home advantage is
unsupported (`model_supplement.json`; `model.py:49`).

`git log -- app_data/model_params.json` places the unchanged artifact at
`da67757`; the workflow does not run `fit_model.py`. Both the original and
current fit script specify TRAIN={2021,2022,2023}, VAL={2024,2025} at lines
19–20. No 2026 training is evident, but the artifact lacks a complete input
hash/run manifest proving exact provenance. Distinguish training from model
selection/validation rather than asserting all five years were fit.

## 4. RAPM, identities and lineup semantics

`fit_rapm.py:40` builds serve phases, counts serving-team wins and joins
lineups. Twenty phase rows independently counted against existing point
records all agree; design rows have +6 total serve exposure and −6 receive
exposure. Positive receive coefficients lower the opponent's serve-win
probability, as intended. The fit weights rallies by .75 per year and uses
ridge alpha 1000 in the current artifact (`fit_rapm.py:135`). This is an
association model of set starters, not exact rally substitutions or causal
replacement effects.

For 18 combinations of rally probabilities and targets 15/25, forward
propagation of every possible rally history agrees with the production DP
to 1.04e-13. An independent 50,000-set simulation per case, seed 20261001,
has maximum standardized discrepancy 1.78. The normal operating checks
therefore support the deuce and fifth-set implementation.

**Bug, low measured size:** at p1=.02, p2=.97, target 15, the fixed 200-step
deuce iteration stops early, producing a .00062523 probability error
(0.0625 percentage points); the reversed case has opposite error. The
independent enumeration has remaining mass below 6.4e-12. This is an
extreme-input boundary failure, not measured typical price error. Require
convergence or solve the linear deuce equations in a later repair.

The pre-merge boxscore review found 372 normalized-name groups with
multiple spellings; all shared jersey numbers and none showed two variants
in the same contest. This supports the near-certain merges but does not
prove identities across transfers, seasons or jersey reuse. Evidence:
`matching-1/player_merge_jerseys.csv`.

The full UI experiment is in `PLAYER_MODEL_AUDIT_2026-10.md`. Four removals
in both modes agree with independent expected calculations. Murray's
hybrid ML falls 3.38pp; Babcock's falls 22.10pp. Sigler's removal *increases*
hybrid ML 1.02pp and Watson's increases it 4.59pp because weights redistribute
among those selected (`rapm_price.py:92`). The no-edit identity promised in
the UI is false for last-match starter defaults, but exact when both sides
select their season reference. Twenty-seven rated teams lack RAPM rosters;
Spring Hill–Kansas raises TypeError. T4 contains concrete design proposals;
no pricing change belongs in this review.

## 5. Prices, stakes and decoder

`kelly.py:24` matches the authorized NCAAF reference WPO formula in
`../Annual_Sports_Main/NCAAF/Python_Asshole_Algo/answer_key.py:27` by source
comparison. There is no added runtime dependency on that project. Logit
blending clips probabilities, combines logits, then applies inverse logit.
`streamlit_app.py:883` gates and stakes on the same selected basis minus
**vig-included** implied probability. Twenty independent Kelly cases pass,
including edge cap and nonpositive edge. Arbitrary negative bankroll/Kelly
inputs are not blocked by these sidebar widgets; validate inputs in a
future repair rather than interpreting out-of-domain stakes.

The synthetic API test verifies home/away decoding, best decimal price
across books, a complete first-priority anchor independent of the best
price, and exclusion of live status. Line-pair keys at `oddspapi.py:116`
normalize away spread signs; integer lines are excluded because the
probability pricer has no push term. Static market/participant dictionaries
remain external-schema risks. Unknown new outcome IDs are not a substitute
for current provider compatibility evidence.

**High bug (Q5):** parse Wisconsin/Nebraska at bankroll $500; the positive
stake is $31.50. Change bankroll to $1,000; the retained card still displays

(`:1024`, `:1065`). A record can combine an old calculation and new metadata.
No real record was written. See `stale_slate.json` and AppTest reproduction.

six final scores, ML, spreads, total pushes and five-set yes/no.

**High bug (Q3):** `bet_log.py:104` searches same orientation within ±1 day
before considering the reverse orientation. An adjacent-day rematch beats
an exact-day reversed fixture. Across 2,287 current-result reversed queries,
26 select another contest. These are affected lookup scenarios, **not 26
proven misgraded owner bets**. Prefer exact fixture identity or rank both
orientations together and refuse ties; audit real exposure read-only first.

Dedupe at `bet_log.py:88` uses date, matchup text and bet text, ignoring book
and odds. That can be intended for paper tracking but does not identify a
fixture robustly. It also does not deduplicate within the submitted batch:
two identical synthetic rows both append. Mock writes establish this only;
no owner log was changed. Header migration at `:65` assumes append-only
schema, checks length rather than exact names, and can write even during
`read_log`. The T3 real read used readonly OAuth scope and bypassed `_ws`.
Mismatched existing headers and concurrent duplicate appends remain risks.

## 10. Runtime, secrets and external requests

containing apiKey, and `streamlit_app.py:802` displays the exception. A
synthetic response with `DUMMY_CREDENTIAL` confirms that the exception string

Sanitize exceptions at the boundary in a separate repair. Local tracked-file

files; filename/pattern checks do not certify the complete public Git history,

sequence raised RuntimeError; its precise final failure cause was not
retained. A subsequent free account check established quota count 4→5 of
250. **One request consumed, zero retries, within T1's four-request cap.**
This proves the empty-board response path, not a current nonempty board's
schema or participant orientation. The remaining allowance was not spent.
Raw evidence is retained; ledger failure is not rewritten as overall success.

App caches have one-hour data/venue and ten-minute live-board lifetimes;
updates can be stale within those intervals. Session cards additionally
persist beyond changed inputs (Q5). Four default books mean up to four
billable requests per uncached full board; 250/month permits 62 full fetches
plus two requests, before other usage. Current application fetch logic has
no durable budget enforcement comparable to this audit's cap. Default
manual news code can invoke paid analysis; audit UI tests block it.

Sheets grading uses one batch and appending uses bulk rows, verified with
mocks. Header migrations and separate operations still consume writes.
Historical sweep has no single-job lock/atomic output protections and its
initial fixture listing is billable; do not run it under T3's zero-call
restriction. No duplicate sweep or persistent service was started here.
